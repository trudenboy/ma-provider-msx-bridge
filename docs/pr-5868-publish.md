# Публикация проверенных ответов в PR #5868

Для выбранных владельцем 47 закрытых веток без ответа используйте
[команды публикации](pr-5868-publication-commands.md) и отдельный режим
`--resolved-unanswered`. Обычный режим ниже выбирает только открытые ветки.

Скрипт: `scripts/publish_pr_review_replies.py`. Нужны Python 3.10+ и
авторизованный `gh` с правом отвечать в PR. Без аргументов — офлайн-просмотр.

Срез 2026-10-08: 83 review threads, все закрыты.
[Thread 83: previous/no-op](https://github.com/music-assistant/server/pull/5868#discussion_r3946368654).
получил ответ владельца и также закрыт. Исправление из provider #270 уже опубликовано. Проверенный head:
`0281933ba52d863301cb3da561de874b06884fc5`; полный upstream CI и PR Checks зелёные.

Черновики для всех веток сохранены в [pr-5868-replies.json](pr-5868-replies.json).
Текст для чтения, ответы на review summaries и общие комментарии — в
[pr-5868-review-replies.md](pr-5868-review-replies.md).
У общих комментариев и review summaries нет статуса открытого обсуждения;
скрипт отправляет ответы только в незакрытые review threads.

1. Найдите запись `number: 83` в JSON, проверьте evidence и исправление.
   Напишите `body` своими словами и установите для этой записи
   `"human_authored": true`. Это требование `CLAUDE.md`, AI Policy Alignment,
   правила 3–4: ответы human-reviewer пишет человек. Оно применяется также
   к bot-thread, если в нём появился человек. Отметка AI Policy в PR
   не заменяет авторство ответа. Для бот-обсуждения без человека достаточно
   проверки текста владельцем перед отправкой.
2. Просмотрите подготовленный текст и выполните проверку без записи:

   ```bash
   python3 scripts/publish_pr_review_replies.py
   python3 scripts/publish_pr_review_replies.py --check
   ```

3. После проверки текста отправьте ответы:

   ```bash
   python3 scripts/publish_pr_review_replies.py --publish --reviewed-by-human
   ```

Скрипт проверяет открытое состояние PR, точный head, последние успешные
GitHub Actions checks `lint`, `test`, `provider-scope`, `Verify`, все страницы
обсуждений и комментариев. Сравниваются ID, автор и полный текст каждого
комментария. Новое открытое обсуждение, изменение кода, комментария или CI
останавливает публикацию. `--check` отдельно сообщает о необходимости
human-authored текста; `--publish` блокируется, пока он не подготовлен.

Перед каждой отправкой проверки повторяются. GitHub не предоставляет
атомарного условия head при создании reply: между последним чтением и POST
остаётся короткое окно для конкурентного изменения. При сетевой ошибке
скрипт останавливается; повторный запуск проверяет маркер и содержимое уже
опубликованного ответа от текущего аккаунта, чтобы не создать дубликат.

Закрытые ветки пропускаются. PR остаётся draft, его описание и состояние
обсуждений не меняются. Скрипт не обновляет ожидаемый head автоматически:
после новых изменений нужно заново проверить исправления и снимок обсуждений.
Не меняйте сохранённые `comments` или `expected_head`, чтобы обойти проверку.
Другой проверенный bundle можно указать через `--bundle PATH`.
