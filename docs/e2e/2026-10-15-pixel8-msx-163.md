# Проверка MSX Bridge 1.6.3 на Android

Дата: 2026-10-15. Проверенный коммит: `980d3109629b2967c4407a7b71f13ba1294d0e41`; PR #298 смержен как `aebaeb332192a2e50fb6297160e4207660ea3fd4`.

Проверялись оба направления: команды MA через его command API с наблюдением Android/MSX и действия в native MSX UI с проверкой MA queue/state. Браузер отклонил доступ к веб-интерфейсу MA: его визуальная проверка не выполнялась и не заменялась обходом разрешений.

## Стенд и границы доказательств

- Pixel 8, Android 17, MSX 0.1.165, управление через авторизованный ADB.
- Отдельный профиль и контейнер; личный профиль MA и существующие остановленные контейнеры не изменялись.
- Начальный официальный MA dev: `15003cae786a704959ce4f3933aea30329545cf0`; итоговый dev после compatibility gate: `70c555ccb1461e4fc62a399e2eca4f62e17a32c8`.
- FFmpeg 9.0.1 в контейнере. Проверены 20 файлов provider между релизной рабочей копией и runtime checkout: расхождений нет.
- Управление, queue identity, source position, число WebSocket и Android audio decoder проверялись раздельно. Запущенный decoder и состояние Playing не доказывают слышимость, отсутствие акустических артефактов или синхронизацию нескольких физических устройств.

Они не объявлены дефектами продукта.

## Исправления по результатам стенда

1. Volume Set менял только MA state. Теперь команда отправляется по WS и вызывает документированный MSX `volume:set`; regression test сначала воспроизвёл отсутствие сообщения, затем прошёл.
2. Search заменял interaction plugin и терял playback connection. Общий `bridge.js` обслуживает main/search, InputHandler передаёт native media events и seek. Добавлены cache busting и запрет кеширования input HTML. Повторная инициализация возвращает меню без второго активного WS.
3. Динамические плейлисты открывали пустой static track list. Теперь карточка динамического плейлиста непосредственно запускает управляемую MA очередь; статичные карточки сохраняют просмотр треков. Failing regression test и реальный native запуск подтверждены.
4. HTTP acceptance script ещё ожидал старый удалённый endpoint. Проверка перенесена на действующий queue endpoint, добавлены 404 всех пяти удалённых путей и новый JS asset.

## Отдельные наблюдения MA core

- `UnsupportedFeaturedException`: StreamFeeder пытается enqueue для MSX без ENQUEUE. Не добавлялась фиктивная capability и не патчился MA core. Наблюдаемые переходы продолжались, но логовая ошибка остаётся.
- При My Wave с унаследованным Repeat All пакет пополнился, однако переход вернулся на старый первый элемент. Эту попытку нельзя считать строгим PASS динамического перехода. `_get_next_index` текущего MA учитывает repeat без проверки dynamic. С Repeat Off повторная строгая проверка перешла на новый queue item из пополнения.
- Пустой Infinite Mix (favorites) на данном профиле не использовался как положительная проверка аудио; рабочий native сценарий выполнен с Infinite Mix (library).

## Отменено и не проверено

30-минутный непрерывный прогон отменён пользователем до запуска. Он не входит в PASS.

В этом выполнении не завершены отдельные сценарии Party guest/add/boost/skip, provider disable/enable, native mute, живого радиоэфира и управления группой. Устройство одно: акустическая синхронизация нескольких телевизоров, Samsung и Xbox не проверялись. Эти ограничения не заменены unit-тестами или состояниями API.

## Завершение стенда

Воспроизведение остановлено. Тестовый встроенный плейлист удалён; shuffle=False, Repeat Off и громкость 100 восстановлены. Тайм-аут экрана возвращён к исходным 30000 ms; временный UI dump удалён. Приватный diagnostic socket удалён, сервер перезапущен обычным запуском без observer на порту 8099; health=ok.

Обезличенные данные: [pixel8-msx-163.json](evidence/pixel8-msx-163.json). Raw logs, screenshots и config snapshots находятся в игнорируемом приватном cache и не публикуются.
