# E2E MSX на Pixel 8 — 9 октября 2026

## Результат

Реальное воспроизведение музыки и тестовых тонов подтверждено пользователем. Базовая библиотека, выбор середины альбома/плейлиста, пауза, навигация по очереди и несколько кодеков работают. Полностью успешного E2E прогона нет: подтверждены ошибки завершения потока/очереди, Repeat One, отключения плеера и восстановления WebSocket; поиск и часы требуют отдельной доработки.

Это проверка Android MSX. Она не заменяет проверку Samsung Tizen и синхронности нескольких физических устройств.

## Подтверждённые ошибки и следующий порядок работы

### 1. Disable не обновляет runtime состояние

`config/players/save(enabled=false)` и последующий `config/players/get` возвращают disabled. Текущий stream останавливается. Однако snapshot продолжает показывать enabled=true/available=true, а новое `player_queues/play_media` успешно запускает The Trooper на телефоне. См. `final-native-results.json`, `lifecycle-results.json`.

Следующий шаг: RED регрессия на настоящем текущем MA Player/config lifecycle; затем обновление конфигурации/состояния retained MSX player и отказ от запуска disabled устройства. Проверить enable без потери регистрации и повтор после server restart.

### 2. Оценочный Content-Length и EOF

В режиме redirect исходный per-player `http_profile=forced_content_length` не даёт естественного перехода пары 8/11 секунд. Android Chromium записывает malformed MP3 packet / PIPELINE_ERROR_DECODE. После изменения только HTTP profile на `chunked` та же пара переходит с index=0 на index=1. Independent MP3/AAC с include_content_length=true также не переходят; false исправляет переход.

Временный обход для Pixel: redirect → per-player HTTP profile Chunked; independent → Include Content-Length=false. Это проверенный обход, а не исправление кода; исходные настройки после прогона восстанавливаются.

Следующий шаг: зафиксировать RED на ошибочной оценке размера, исключить ложный Content-Length либо передавать точный размер. Проверять отдельно MA Streamserver redirect и independent proxy. Не менять кодек вслепую.

### 3. Конец очереди и Repeat One

Chunked 3-item fixture без ручного Next: 0→1→2. После EOF последнего item MA продолжает показывать PLAYING вместо завершения. Repeat One проходит 0→1→2, несмотря на repeat_mode=one. Repeat All проверен положительно: 0→1→2→0→1.

Следующий шаг: RED для native completion + Repeat OFF/ONE/ALL, синхронизация completion с MA queue semantics. streams=0 само по себе не доказывает тишину: короткий файл может быть уже целиком буферизирован на телефоне.

### 4. Переподключение WebSocket после restart

После штатного server restart MA ready, но MSX не создаёт новый WS. В `plugin.html` обработчик close намеренно не повторяет соединение для кодов 1000/1001; штатное закрытие провайдера попадает в этот путь. Force-stop/reopen + launcher возвращает прежний ID и один WS.

Следующий шаг: воспроизводимый client lifecycle тест, переподключение при временном shutdown/restart с backoff и защитой от устаревшего socket; отдельно проверить постоянное отключение/удаление провайдера.

### 5. Native поиск и часы/seek

Экранные кнопки действительно ввели Latin query, UI остался busy. Прямой search-input endpoint возвращает результаты. Два scoped packet capture не увидели search-input GET от телефона; первопричина пока не установлена. Ошибка native input не выдаётся за ошибку HTTP поиска.

Native duration показывает 00:00:00, Forward не даёт скачка позиции. MA seek/resume создаёт новую served timeline, native clock расходится с source position MA. Следующий шаг: разделить ограничения устройства и ошибки отображения; проверить native input submit и position/seek протокол на Pixel, затем Tizen. Слышимость музыки не доказывает точность seek.

### Дополнительные наблюдения

- Текущий MA feeder вызывает enqueue_next_media на MSX без объявленного enqueue support и пишет UnsupportedFeaturedException. Это integration предупреждение; его связь с EOF не доказана.
- Native Party показывает QR; подпись Scan to join the party накладывается на нижнюю часть кода. Реальное считывание камерой не проводилось, повреждение сканируемости не утверждается.
- Возвращение старого 500-item плейлиста из раннего сценария **не считается подтверждённой ошибкой**: fallback tap автоматизации попал по library tile, когда player panel отсутствовал. Чистая очередь проверена отдельно. В `native-context-repro-results.json` этому прогону поставлен valid=false. Нельзя засчитывать скрытую кнопку или лишнее нажатие как Next.
- Начальная codec matrix была ошибочно подписана AAC/FLAC, пока per-player output_codec оставался MP3. Итоговый `format-results.json` перезаписан исправленной матрицей с actual MIME; первоначальные подписи не использованы в итогах.
- Первоначальный invalid-token запрос без URI правильно получил 400. Исправленный тест с valid URI получает 403; первоначальный тест не был дефектом продукта.

## HTTP gate и воспроизведение проверок

Живой HTTP gate повторён в конце прогона: **50/50 PASS**, exit code 0. Это status/shape smoke и негативные проверки, не доказательство полной семантики поиска или физического playback.

```bash
rtk proxy .venv/bin/python docs/e2e/live-http-checks.py \
  --base-url http://192.168.10.229:8099 \
  --output .cache/pixel8-e2e/http-results.json
```

Скрипт возвращает ненулевой exit code при несовпадении ожидаемого статуса. Bootstrap requests могут зарегистрировать IP-derived локальный MSX player; музыка не запускается. Ruff check/format для скрипта пройдены. Повторный unit suite не запускался: исходники провайдера не менялись.

Основные приватные артефакты в `.cache/pixel8-e2e/` (каталог mode 0700):

- `http-final-results.json` — 50 HTTP результатов без media tokens.
- `format-results.json`, `independent-*-audio.txt`, `independent-*-network.txt` — actual codec/audio/header evidence.
- `repeat-end-results.json` — последовательности OFF/ONE/ALL.
- `final-native-results.json`, `ma-control-boundaries.json` — controls/seek/disabled state.
- `lifecycle-results.json` — stop, remove/re-register, idle.
- `native-party-active.png`, `native-artist-detail.*` — устройство, не mock UI.
- `check-natural.py` — RED-capable real-device loop, требующий временного observer и fixture server; после восстановления стенда они отключены.

Raw snapshots и packet captures могут содержать подписанные media URLs. Они остаются локально и не предназначены для PR/публичной публикации. В этот отчёт токены, credentials и Party guest URL не включены.

## Восстановление и ограничения

Восстановление завершено и проверено:

- Defaults album/playlist=replace; output_codec=mp3; HTTP profile=forced_content_length; provider redirect/mp3/include_content_length=true/stop_notification=false/idle_timeout=30. Все изменённые значения сверены с сохранёнными original config responses.
- Repeat off/shuffle false, volume=100; перед остановкой контейнера queues idle / active streams=0.
- Исходный Docker image и три bind mounts сохранены, возвращён обычный `python -m music_assistant` entrypoint; health 200, players=1. Observer source перемещён в приватные артефакты, socket удалён.
- HTTP fixture process завершён; порт 8098 закрыт. Временные tcpdump captures завершены; временная установка tcpdump исчезла вместе с диагностическим контейнером.

- Исходный forced Content-Length восстановлен несмотря на найденную несовместимость; проверенный обход Chunked описан выше, автоматически постоянной настройкой не оставлен.

Исходный профиль `.ma-data/` не изменялся. Тестовая библиотека и артефакты сохраняются для повторной диагностики. Второго MSX для Universal Group нет; Samsung Tizen в этом прогоне не участвовал; native duplicate selection, неактивный Party, QR scan и точный слышимый seek остаются непроверенными.
