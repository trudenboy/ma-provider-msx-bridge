# Руководство по возможностям

Подробная документация по расширенным возможностям MSX Music Assistant Bridge.

## Браузерный веб-плеер

Браузерный веб-плеер и киоск больше не входят в этот провайдер.
Для всегда включённых экранов используйте отдельный провайдер Web Kiosk.

## Группировка плееров (Экспериментально)

Синхронное управление воспроизведением на нескольких телевизорах. Важно: эта функция синхронизирует команды play/pause/stop/next/prev, но не синхронизирует сами аудиопотоки — каждый TV получает свой независимый поток, поэтому возможны небольшие расхождения во времени между устройствами.

### Сценарии использования

- **Умный дом** — Одна музыка в гостиной и на кухне одновременно
- **Ресторан/Кафе** — Синхронная фоновая музыка на всех экранах
- **Магазин** — Синхронизированное аудио по всему торговому залу
- **Вечеринка** — Музыка играет в нескольких комнатах одновременно

### Настройка

1. Включить `enable_player_grouping` в настройках MA (по умолчанию включено)
2. Открыть веб-интерфейс MA
3. Перейти в раздел Players
4. Выбрать несколько MSX плееров
5. Создать группу
6. Запустить музыку — все TV в группе играют синхронно

### Как это работает

```
Команда группы MA
      │
      ▼
┌─────────────┐
│ Group Leader│ (первый TV в группе)
│   msx_tv1   │
└──────┬──────┘
       │ передача команды
       ├─────────────────┐
       ▼                 ▼
┌─────────────┐   ┌─────────────┐
│   Участник  │   │   Участник  │
│   msx_tv2   │   │   msx_tv3   │
└─────────────┘   └─────────────┘
```

### Режимы стриминга для групп

Опция `group_stream_mode` управляет способом стриминга аудио на сгруппированные плееры:

| Режим | Описание | Применение |
|-------|----------|------------|
| `independent` (по умолчанию) | Каждый TV получает свой ffmpeg процесс | Максимальная совместимость, чуть выше нагрузка на CPU |
| `shared` | Один ffmpeg процесс, несколько читателей | Меньше нагрузка на CPU, лучше для многих TV |

```
Режим Independent:
┌─────────┐     ┌─────────┐     ┌─────────┐
│ ffmpeg  │     │ ffmpeg  │     │ ffmpeg  │
└────┬────┘     └────┬────┘     └────┬────┘
     │               │               │
     ▼               ▼               ▼
   TV 1            TV 2            TV 3

Режим Shared Buffer:
            ┌─────────┐
            │ ffmpeg  │
            └────┬────┘
                 │
        ┌────────┼────────┐
        ▼        ▼        ▼
      TV 1     TV 2     TV 3
```

### Ограничения

- **Нет синхронизации аудиопотока** — каждый TV получает свой независимый аудиопоток, поэтому время воспроизведения может отличаться на 100-500мс+ между устройствами
- Громкость синхронизируется, но на некоторых TV может потребовать индивидуальной настройки
- Экспериментально: возможны проблемы с 3+ TV при плохом качестве сети
- Все TV в группе должны быть на одном MA сервере
- Не подходит для сценариев, требующих точной синхронизации аудио (например, несколько колонок в одной комнате)

### Устранение неполадок

**Проблема:** Один TV в группе не воспроизводит
- Проверьте WebSocket соединение в инструментах разработчика браузера
- Убедитесь, что TV зарегистрирован в списке Players MA
- Попробуйте удалить и заново добавить TV в группу

**Проблема:** Значительная задержка между TV
- Проверьте сетевую задержку между сервером и TV
- По возможности используйте проводной Ethernet
- Уменьшите размер группы

## Нативные плейлисты MSX

Бесшовная интеграция очереди MA с навигацией по плейлистам MSX для естественного воспроизведения альбомов и плейлистов.

### Сценарии использования

- **Прослушивание альбома** — Выбрать альбом → все треки добавляются в очередь MSX → next/prev работают на пульте TV
- **Воспроизведение плейлиста** — Запустить плейлист в MA → TV показывает текущий трек и позволяет переключать
- **Управление из MA UI** — Переключить трек в MA → TV автоматически переключается

### Как это работает

При воспроизведении альбома или плейлиста:

```
1. MA создаёт очередь со всеми треками
   [Трек 1] [Трек 2] [Трек 3] ...

2. MSX Bridge генерирует нативный MSX плейлист
   {
     "type": "list",
     "items": [
       {"title": "Трек 1", "action": "audio:..."},
       {"title": "Трек 2", "action": "audio:..."},
       ...
     ]
   }

3. MSX плеер загружает плейлист
   ┌─────────────────────┐
   │ ▶ Трек 1  3:45      │
   │   Трек 2  4:12      │
   │   Трек 3  3:58      │
   └─────────────────────┘

4. Навигация пультом TV работает естественно
   [◄ Пред] [▶ Воспр/Пауза] [След ►]
```

### Синхронизация очереди

```
Очередь MA ←→ Плейлист MSX
     ↓              ↓
[Трек 1]     [Трек 1] ▶ Играет
[Трек 2]     [Трек 2]
[Трек 3]     [Трек 3]
```

При смене трека в MA UI:
1. MA отправляет WebSocket сообщение в MSX
2. MSX плагин получает команду `goto_index`
3. MSX плеер переключается на нужный трек
4. Аудиопоток переключается бесшовно

### Возможности

- Двусторонняя синхронизация между MA и MSX
- Сохранение позиции трека при паузе/возобновлении
- Поддержка режимов shuffle и repeat (через MA)
- Отображение обложки для каждого трека

## Двусторонняя синхронизация WebSocket (🚧 В разработке)

Синхронизация состояния в реальном времени между MA UI и MSX плеером.

### Планируемые возможности

- **Отслеживание позиции** — Позиция воспроизведения отображается в MA UI в реальном времени
- **Синхронизация паузы/возобновления** — Пауза на TV отражается в MA и наоборот
- **Обновления в реальном времени** — Мгновенные уведомления без polling

### Текущее состояние

Реализовано:
- MA → MSX: Команды Play, Stop, Pause
- MA → MSX: Уведомления о смене трека
- MSX → MA: Регистрация плеера

В разработке:
- MSX → MA: Обновления позиции
- MSX → MA: Изменения состояния воспроизведения

## WebSocket переподключение с jitter

Надёжная обработка WebSocket соединения с экспоненциальным backoff и jitter.

### Как это работает

При потере WebSocket соединения:

```
Попытка 1: Ожидание 1с + случайное(0-500мс)
Попытка 2: Ожидание 2с + случайное(0-500мс)
Попытка 3: Ожидание 4с + случайное(0-500мс)
Попытка 4: Ожидание 8с + случайное(0-500мс)
...
Макс. ожидание: 30с + случайное(0-500мс)
```

### Преимущества

- Предотвращает перегрузку сервера при одновременном переподключении нескольких TV
- Изящная обработка временных сетевых проблем
- Автоматическое восстановление без вмешательства пользователя

### Конфигурация

Поведение переподключения автоматическое и не требует настройки. Если нужно переподключиться вручную:

1. Обновить MSX приложение на TV (обычно: Menu → Reload)
2. Или полностью перезапустить MSX приложение
